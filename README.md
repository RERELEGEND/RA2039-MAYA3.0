# MAYA 3.0 — 个人智能体操作系统

> 不是又一个聊天机器人，而是属于你的 AI 伙伴。
> *Not just another chatbot; it's your AI agent with persistent memory, real-time awareness, and multi-interface support.*

**核心能力：**

- **持续记忆** (Persistent Memory) — 跨会话记住你们之间发生的一切
- **语音优先** (Voice-Native) — 能听会说，像伙伴一样自然对话
- **硬件感知** (Hardware-Aware) — 手表、耳机、智能家居……感知你的身体与环境
- **多端一致** (Multi-Interface) — Web / 桌面 / 终端 / 语音，同一个智能体、同一份状态

## 项目概览

**MAYA 3.0 是什么？**

MAYA 3.0 是一个面向开发者的开源 **个人智能体操作系统**（Personal Agent OS）。它不是单次问答工具，而是一个**常驻**的智能体运行时：拥有自己的状态机、自己的记忆库、自己的工具与感知通道，并通过统一的多层架构，把 Web、桌面、终端、语音与可穿戴设备收敛进**同一个智能体会话**。

我们采用 **Docs-First** 策略：先发布定位与架构文档（即本仓库当前内容），再分阶段逐步开放源码，让社区在设计阶段即可参与讨论。

**为什么是 MAYA，而不是一个聊天机器人？**

| | 聊天机器人 | MAYA 3.0 |
|---|------------|----------|
| 身份 | 每次对话重新开始 | 常驻智能体，有连续状态 |
| 记忆 | 会话窗口 | 数据库持久化 + 情景记忆，跨会话 |
| 形态 | 单一聊天框 | Web / 桌面 / 终端 / 语音多端一体 |
| 感知 | 无 | 身体体征、设备、环境（可扩展） |
| 行动 | 只回答 | 经权限控制的工具执行 |

**核心设计取舍**

- **持续记忆**：所有对话、状态与知识持久化存储，智能体跨会话保留上下文（情景记忆按 `session / workspace / global` 分级，敏感信息脱敏）。
- **多端一致**：同一个智能体同时服务 Web 界面、桌面端、终端与语音设备，所有入口共享会话与状态，任一端的对话另一端无缝续接。
- **语音优先**：原生集成语音识别与合成，支持唤醒、打断、多轮对话；语音与文本在会话中互为等价通道。
- **模块化可扩展**：工具调用体系（MCP 风格）与分层架构，使开发者能接入新工具、外部 API 与各类传感器，而不触碰核心。
- **权限可控的行动力**：工具执行经分级权限裁决，危险操作需显式确认，让"会行动"与"可信任"并存。
- **Docs-First**：完整设计文档先行；即使源码未开放，开发者也能先理解架构并参与路线讨论。

## 核心能力

### 🧠 持续记忆
- 会话状态（八域 State）可快照 / 恢复，多端共享。
- **情景记忆**：数据库全文检索，自动沉淀每次交互，让智能体"记得过去"。
- **身体记忆**：可穿戴体征数据在征得同意后写入记忆，供后续会话调用。

### 🗣 语音原生交互
- 语音识别（ASR）+ 语音合成（TTS），云后端与本地可切换。
- 唤醒词、静音检测、说话打断（Barge-in）、多轮语音会话。
- 无独立声卡 / CI 环境可降级到仿真后端，保持全链路可测。

### 🖥 多通道 · 同一智能体
- **Web 主交互面**：Stage 沉浸式主页与 Web 控制台。
- **桌面端**（Qt5）与 **命令行**（CLI）：与 Web 共享同一会话与状态。
- 一个 CM 会话语义层统一各端，不各自为政。

### 🔌 工具与插件执行
- 文件 / 终端 / Git / 数据库 / 网络等多类 MCP 风格工具服务。
- 分级权限（Level / Mode），执行前裁决、危险操作确认。

### 📡 硬件与传感器感知（RA2039 扩展）
- **BioSense 体征网关**：接收 Galaxy Watch（WebSocket 遥测）与 iPhone Health 数据上报，落库供智能体取用。
- **IoT 空间可视化**：以 3D 场景呈现智能家居与设备状态（规划扩展 Home Assistant 生态）。
- 音频采集 / 播放抽象层，支持真实设备与仿真后端。
- 设计上与 ROS 2 Humble 兼容可共存（主链路不依赖 ROS）。

### 🧭 会话与治理
- 明确的对话状态机（听 → 想 → 说），支持打断与播报控制。
- 单用户本地优先（默认 `owner_id=local`），数据留在你自己的设备上。

## 🏗 系统架构（概览）

```
┌───────────────────────────────────────────────────────────┐
│  入口层  Web(Stage/控制台) · Qt5 · CLI · 语音 · 可穿戴      │
└──────────────────────────────┬────────────────────────────┘
                               ▼
        ┌──────────────────────────────────────────┐
        │  会话管理层 CM (会话状态机 · 三端接入)      │
        │  · 统一会话/状态 · 打断编排 · UI 托管       │
        └───────┬───────────────────────┬──────────┘
                ▼                       ▼
   ┌────────────────────┐   ┌────────────────────┐
   │  智能体内核 Agent    │   │  语音引擎 Voice      │
   │  推理/状态/记忆/工具 │   │  ASR·TTS·唤醒·VAD    │
   │  权限裁决 · 事件总线  │   │  （多轮，轮询 CM 指令）│
   └─────────┬──────────┘   └────────────────────┘
             ▼
   ┌────────────────────┐
   │  感知网关 BioSense   │ ← 手表 / 手机 / 设备
   │  体征·环境数据落库    │
   └────────────────────┘
```

- **分层单向依赖**：内核（Agent）← 会话管理（CM）← 语音/硬件入口，边界清晰、可替换。
- **多进程服务**：各子系统独立进程，按端口协作（详见仓库内文档）。
- **技术栈**：Python 3.10+ · FastAPI · SQLite(FTS5) · Redis(事件总线) · WebGL/Three.js（可视化）· Qt5（可选桌面端）。

> 详细端口 / 层间契约 / 目录白皮书将在下一阶段随文档仓库开放。
